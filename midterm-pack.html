Topic 1 — Threats, Risks & Vulnerabilities

Core distinction

Data security vs information privacy

Data security protects data from theft, unauthorised disclosure, alteration, corruption or loss of availability.

Information privacy controls who can access personal information and how it is collected, used and shared. Collection should be necessary, transparent and appropriately consented to.

Memory: security protects the data; privacy protects the person and the use of their information.
Five properties

CIA + privacy properties

ConfidentialityOnly authorised parties may access the data.
IntegrityData remains correct, authentic and unmodified.
AvailabilityAuthorised users can access data/resources when needed.
AnonymityAn action cannot be linked to the real identity.
IndistinguishabilityAn individual cannot be singled out from others in released data.

Property → defence mapping

PropertyDefenceWhy
ConfidentialityEncryption + access controlOnly authorised/key-holding users can read data.
IntegrityHashing + logsDetect modification and record actions.
AvailabilityBackupsRestore data/service after loss or lockout.
Anonymity / indistinguishabilityDe-identificationReduce the ability to link released data to one person.
Trap: encryption is not the lecture's integrity control; hashing/logs are. Backups support availability.

Four re-identification attack families

AttackMeaningMemory example
InferenceLearn or predict sensitive facts from released data.AOL search history.
AmplificationLink released/anonymised data with external/public data to learn more.Medical data + public profile.
DifferencingCompare results with and without a target; the difference reveals the target.Diagnosis count queries.
ReconstructionRebuild original or individual-level information from aggregate/synthetic releases.Mobility trajectories.

Auxiliary knowledge

Direct / unique identifiersIdentify a person directly: email, phone, medical record number, etc.
Quasi-identifiers (QIDs)Not necessarily unique alone, but combinations can identify a person.
Background knowledgeFacts the adversary already knows about the target.
Key lecture statistic used in the course: about 87% of the US population could be uniquely identified by gender + date of birth + 5-digit ZIP in the cited Sweeney result.

Topic 2 — Privacy Risk Quantification & Evaluation

Four elements that make data risky

ElementMeaningExample
UniquenessRare values/combinations make a record stand out.Rare “Jenjira” vs common “John”.
UniformityRepeated values for the same person increase inference confidence.Repeated searches about one illness.
Linkable tokensPII-containing values that can link a record to a person.Email embedded in free text.
CorrelationOne known attribute helps infer another or link records across datasets.Part-time work ↔ late-submission penalty.

Threat models

A threat model states what the adversary is assumed to know/can do. More usable knowledge generally means higher re-identification risk.

TM1Postcode only.
TM2Medical code only.
TM3Both postcode and medical code.
Lecture conclusion: TM3 is conceptually highest risk because combining attributes produces more specific/unique patterns.

Privacy spectrum

0.0Absolute privacy.
0.25Low suspicion.
0.5Moderate suspicion.
0.75High suspicion.
1.0Provably exposed.

Entropy

Shannon entropy measures uncertainty/information in bits.

H(X) = − Σ p(x) · log₂ p(x)
0.5 / 0.51.000 bit
0.6 / 0.40.971 bits
0.8 / 0.20.722 bits
1.0 / 0.00 bits
Course interpretation: more spread-out / more unique values can expose more identifying information to the adversary, so higher entropy can correspond to higher re-identification risk in these examples.

IG and RIG

Information Gain (IG) measures how much information about original X is revealed by released/de-identified Y. Lower IG means less leakage.

Relative Information Gain (RIG) normalises the leakage by H(X).

H(X|Y) = Σ p(y)H(X|Y=y)
IG = H(X) − H(X|Y)
RIG = IG / H(X)
The Peter/Pete/Smith encoding example contains a lecturer-confirmed issue in the printed figures. Use the calculation workflow rather than memorising one disputed RIG value.

Topic 3 — De-identification Methods

Five basic de-identification techniques

Remove direct identifiersDelete direct identifiers such as name, email, phone or medical number.
AggregationRelease group statistics instead of individual rows.
BinningReplace detailed values with ranges.
PerturbationAdd random values/noise or otherwise alter values.
Synthetic dataRelease artificial records intended to mimic real distributions.
These methods are not automatically safe; background/auxiliary data can still support linkage or inference.

k-anonymity

Each released record must be indistinguishable from at least k−1 other records with respect to the selected QIDs.

k = 3 → every released QID pattern appears in at least 3 records.

Generalisation replaces a precise QID with a broader value. Suppression removes/masks a value when needed to reach the required grouping.

Health-data example: nationality, age and ZIP are QIDs; health condition is the sensitive attribute. Larger k normally gives more ambiguity but increases information loss.

Main weaknesses: homogeneity attack and background-knowledge attack.

Homogeneity vs background-knowledge attack

AttackWhy k-anonymity can fail
HomogeneityA QID class contains multiple records but the sensitive value is identical or nearly identical for all of them, so the sensitive fact is still revealed.
Background knowledgeExternal facts about the target eliminate possible sensitive values inside the class.
k-anonymity mainly reduces uniqueness/linkage certainty; it does not guarantee sensitive-value uncertainty.

l-diversity

Extends k-anonymity by requiring each equivalence class to contain at least l well-represented sensitive values.

l = 3 → each class should contain at least 3 diverse sensitive values.

The lecture health example uses values such as Heart, Flu and Cancer inside each group.

Designed to address the sensitive-value homogeneity weakness of k-anonymity and strengthen protection against background knowledge.
Remaining weaknesses: similarity attack and composition attack.

Similarity vs composition attack

AttackMechanism
SimilarityValues are technically different but semantically close, so the category can still be inferred. Example: gastric ulcer, gastritis and stomach cancer all reveal a stomach-related condition.
CompositionMultiple anonymised releases are combined, and what is safe separately may leak information together.

t-closeness

Requires the sensitive-value distribution inside each equivalence class to remain close to the sensitive-value distribution in the full dataset.

distance(class distribution, overall distribution) ≤ t

The lecture uses Earth Mover's Distance (EMD) as the closeness measure and includes an example of approximately t = 0.278.

t-closeness controls distribution leakage and helps address the semantic-similarity weakness of l-diversity.
Cost: stronger protection often requires more generalisation/suppression, so utility falls. The privacy–utility balance is harder.

k vs l vs t — master comparison

ModelMain ruleImprovesRemaining weakness / cost
k-anonymity≥ k records share a QID patternUniqueness/linkage ambiguityHomogeneity + background knowledge
l-diversity≥ l diverse sensitive values/classSensitive-value diversitySimilarity + composition
t-closenessClass distribution close to full-data distributionDistribution/semantic leakageGreater information loss / harder utility trade-off
High-value exam fact: the model vulnerable to homogeneity attack is k-anonymity.

Probable vs provable privacy

Provable privacy means the privacy guarantee is supported by mathematical/theoretical proof against a defined attack/model. Probable privacy may reduce risk but does not prove that the guarantee always holds.

Topic 3 focuses on k-anonymity, l-diversity and t-closeness; provably private approaches are introduced as later material rather than part of this midterm scope.

Formula & Calculation Reference

Core formulas

H(X) = − Σ p(x)log₂p(x)
H(X|Y) = Σ p(y)H(X|Y=y)
H(X|Y) = H(X,Y) − H(Y)
IG = H(X) − H(X|Y)
RIG = IG / H(X)

Entropy workflow

  1. Read the threat model and identify what counts as one value (single attribute or attribute pair).
  2. Group identical values and count each group.
  3. Compute p = count / total.
  4. Compute −p log₂p for every group.
  5. Add the contributions.
  6. Write the unit: bits.
  7. Interpret relative to the compared model/dataset.

Conditional entropy / IG / RIG workflow

  1. Compute H(X), the original entropy.
  2. Group records by released value Y.
  3. Inside each Y group, compute remaining uncertainty H(X|Y=y).
  4. Weight each group by p(y) and sum to get H(X|Y).
  5. IG = H(X) − H(X|Y).
  6. RIG = IG / H(X).
  7. Interpret: smaller IG/RIG = less original information exposed.
Shortcut check: H(X|Y) can also be obtained from H(X,Y) − H(Y) when those quantities are available.

Reading k, l and t from a table

k: group rows by identical QIDs; the smallest equivalence-class size determines the maximum k satisfied.

l: inside every class count well-represented/distinct sensitive values; the least-diverse class determines l.

t: compare each class's sensitive distribution with the full-data sensitive distribution; every class must stay within the threshold t.

Do not confuse k with the number of distinct sensitive values. k counts rows in a QID class; l concerns diversity of the sensitive attribute.

Calculation checklist

  • State the formula before substituting numbers.
  • Show counts and probabilities.
  • Keep enough decimal places until the final answer.
  • Entropy / IG are in bits; RIG is a unitless ratio.
  • Check probabilities sum to 1.
  • For joint tables, verify marginals reproduce the single-attribute counts.
  • Finish with an interpretation sentence.

Answer Patterns & Common Traps

Definition

“Define X”

Use: purpose → rule/mechanism → one example or limitation.

Example: “k-anonymity makes each record indistinguishable from at least k−1 others on the chosen QIDs, usually using generalisation/suppression. Larger k increases ambiguity but usually increases information loss.”
Comparison

“Compare k, l and t”

Use: rule → attack/problem improved → remaining weakness → utility cost.

Scenario

“What attack is this?”

Same sensitive values → homogeneity. Outside facts → background knowledge. Semantically close values → similarity. Two releases combined → composition. Public+anonymous linkage → amplification. Query-result difference → differencing.

Calculation

“Calculate risk / entropy / IG”

Show counts → probabilities → formula → substitution → numeric result → units → interpretation.

High-value traps

Removing names makes data anonymous.False. QIDs/background data may still re-identify.
k-anonymity automatically hides the sensitive value.False. Homogeneity can reveal it.
l=3 means three records.False. It refers to sensitive-value diversity inside each class.
Different sensitive values always prevent inference.False. They may be semantically similar.
Larger k is always better overall.False. Privacy generally rises but utility can fall.
t-closeness gives stronger privacy with no cost.False. More generalisation/information loss may be required.
Encryption is the lecture's integrity control.False. Encryption/access control → confidentiality; hashing/logs → integrity.
